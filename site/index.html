02 / Trust boundary

The host lends
reads, never writes.

01

Chain configuration and block context select current or historical rules—not a wall clock or arbitrary flag.

request →
02

Worker executes

A digest-verified binary asks for parent-bound account, code and storage reads in a Linux sandbox.

deltas →
03

Host validates

The worker returns receipts and explicit deltas. The host checks bindings, validates roots, then commits or unwinds.

No shared Rust objects. No writable database handle. Versioned serialized messages bind operation, configuration, parent, candidate and executable identity. Infrastructure failures fail closed—never silently back to current rules.

05 / Ethereum context

Related direction.
Different job.

EIP-4444 / history expiry

Allows clients to stop serving older block bodies and receipts after a retention window. Base Era does not implement that policy: historical bodies remain in the host source and data remains available to this demo.

Read EIP-4444 ↗

State expiry / statelessness

Ethereum’s statelessness roadmap concerns access to state and witnesses. This spike passes immutable parent-state reads to a native worker; it neither expires state nor introduces a state-expiry scheme.

Ethereum roadmap ↗

Era / Era1 files

Era is a standardized archival file family for historical chain data. “Era” here names an execution-version experiment. It is not an Era/Era1 archive-format implementation.

06 / Limits

A boundary demo,
not a finished client.

  • Historical bodies remain.Selected paths bypass them, but the host tree and dependencies are not physically history-free.
  • Parity is not proof.Native stateless execution matched headers 19–21; no zkVM guest, proof or onchain authorization was demonstrated.
  • Coverage is scoped.Supported historical calls, estimates and traces work; every simulation API and custom tracer does not.
  • Isolation has a platform.Landlock 3+, seccomp and other Linux controls fail closed on unsupported kernels; the worker remains trusted client code.
  • No expiry feature.This does not implement Ethereum state expiry or EIP-4444 history expiry.
  • Production work remains.Resource budgets, persistent/batched workers, caching, broader corpora, artifact governance and proof integration.
